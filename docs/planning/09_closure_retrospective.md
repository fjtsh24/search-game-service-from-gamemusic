# 09. サービスクローズの判断と振り返り

- 判断日: 2026-11-12
- 結論: **公開停止＋リポジトリアーカイブ**（削除はしない）

## 1. クローズ理由

「健全に発展できるか」を 3 観点で評価し、いずれも満たせないと判断した。

| 観点 | 状態 | 改善の見通し |
|---|---|---|
| データ品質 | タグ付与率 約22%（コア機能の類似度がほとんどのゲームで効かない）。`games.youtube_video_id` の 31% が OST と無関係（#105） | 98% カバーが見込める唯一の手段は Steam ストアページのユーザータグのスクレイピング（Tier 2） |
| データ取得の正当性 | 他所の画像 URL の直接参照、非公式エンドポイント・スクレイピングへの依存（#33） | 公式 API にユーザータグは無く、SteamSpy も 403。正当な代替ソースが無い |
| 需要 | 利用者は開発者本人のみ。計測（#22）未導入 | 品質が前提のため「データ品質」に戻る |

**構造的な問題:** 品質を上げる手段（スクレイピング）が正当性を損ない、正当性を守ると品質が頭打ちになる。どちらに進んでも健全な発展にならない。

## 2. 得られたもの

- 問題意識「音楽の好みという軸でゲームを探す」は今も有効。否定されたのは仮説ではなく、**それを支えるデータの調達手段**。
- 企画（JTBD・ペルソナ・ストーリーマップ）〜 ベータリリースまでの一連の設計資料（01〜08）。
- 学び: 「データが主役のサービス」は、企画初期に **正当に・継続的に取得できるデータソース** を最初に検証すべきだった。

## 3. 再開の条件（参考）

- ゲーム音楽の雰囲気タグを提供する公式・ライセンス付きのデータソースが現れる
- または、外部取得をやめて手動キュレーション規模に縮小し、それを本人が楽しめる

## 5. 公開リポジトリとして残すものの倫理チェック

方針: 残せるものは残し、技術者倫理上の問題があるものだけ除く。

| 対象 | 判断 | 理由 |
|---|---|---|
| アプリ・設計資料・`supabase/schema.sql` | 残す | 自作物。第三者の権利を含まない |
| `scripts/` のデータ取得スクリプト | 残す（README に実行しない旨を明記） | ウェイト付きで行儀は悪くないが、非公式エンドポイント依存のため第三者が流用しないよう注意書きを付ける |
| User-Agent の連絡先メールアドレス | 削除 | 第三者がスクリプトを流用すると、そのアクセスが本人の連絡先名義で Steam に送られてしまう |
| 収集済みデータ（DB ダンプ） | リポジトリに入れない | Steam ストア説明文（著作物）・他所の画像 URL・YouTube 動画 ID などの第三者コンテンツを再配布することになる |
| 未マージのブランチ `fix/homepage-cache-and-region` | リモートにそのまま残す | 問題なし |
